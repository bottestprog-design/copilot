# تقرير المراجعة اليدوية والإصلاح — LocalAI Creative Studio 1.11.3

**النطاق:** مراجعة مصدر الإصدار المنشور داخل `LocalAI-Creative-Studio-v1.11.2-Fixed/LocalAI-Creative-Studio` على فرع `main`، ثم تجهيز إصلاحات على فرع مستقل. هذا تقرير مراجعة مصدرية، وليس شهادة تشغيل على Windows أو GPU.

## إصلاحات هذه الجولة

1. استعادة `.gitignore` داخل حزمة الإصدار نفسها، وتصحيح بصمته في `MANIFEST-SHA256.txt`. كان الـ Manifest يسجل الملف، لكن الملف كان موجوداً في مجلد مشروع آخر وليس داخل مجلد الحزمة المستهدفة؛ لذلك كان التحقق الصارم يرفض الحزمة.
2. تصحيح `CHECK-STUDIO.ps1` لاستخدام `/api/health` عند فحص ComfyUI وOllama. مسار `/api/ready` مخصص لجاهزية تطبيق Studio ويعيد الإصدار واسم التطبيق فقط، ولا يعيد حالة المحركات.
3. إضافة حواجز تمنع القراءة أو الكتابة إلى ملفات بيانات التطبيق إذا كانت مجلدات أو Reparse Points، لملفي حالة الاعتماديات وحالة تثبيت سطح المكتب.
4. تحسين معاملة التحديث: أخذ النسخ الاحتياطية قبل إيقاف الخدمة، التحقق من SHA-256 لكل نسخة احتياطية بعد نسخها، تسجيل بصمتها، والتحقق من البصمة مرة أخرى قبل الاستعادة وبعدها. كما ينتظر المحدّث تحرير المنفذ 7865 قبل استبدال ملفات التطبيق.
5. عند فشل التحديث، وبعد الاستعادة، يعيد تشغيل خدمة Studio فقط إذا اكتشف أنها كانت تعمل قبل بدء التحديث، ومن دون فتح نافذة متصفح إضافية.
6. إصلاح المكتبة لعرض جميع مخرجات المهمة الواحدة، بدلاً من أول ملف فقط، مع إظهار عدد النتائج في البطاقات المختصرة. كما أضيفت حالة `submitting` إلى التسميات.
7. تعديل رسالة إيقاف الطابور لتوضح عندما يرفض الخادم الإيقاف لأن المهمة الجارية ليست مهمة ثبت أنها تابعة للاستوديو.

## نقاط تم التحقق منها بمراجعة المصدر

- مسارات البرنامج منفصلة عن مجلد بيانات المستخدم، وأداة التحديث لا تستخدم `robocopy /MIR`.
- مسار بيانات Studio يُستعاد من علامة `CreativeStudioDataRoot.txt` ويدعم الموقعين المعروفين: `%LOCALAPPDATA%\LocalAI\CreativeStudioData` و`D:\LocalAI\CreativeStudioData`.
- الخادم يقبل عناوين Loopback فقط لخدمات ComfyUI وOllama، ويعمل على `127.0.0.1:7865`.
- منطق حذف الطابور يستهدف المهام المسجلة من Studio فقط؛ ومنطق interrupt لا يطلب إيقاف محرك ComfyUI إلا عندما تكون المهمة الجارية الوحيدة معروفة على أنها مهمة Studio.
- تمت مراجعة ملفات JSON الستة مع ملفات الإعداد المقابلة: أسماء الملفات متطابقة، ومراجع العقد والـ bindings المشار إليها موجودة داخل كل رسم.
- تمت مطابقة مراجع عناصر HTML مع المحددات الثابتة في JavaScript؛ المحددان غير الموجودين كـ IDs ثابتة (`clear-reference` و`map-task`) يُنشآن ديناميكياً في الواجهة، ولا يمثلان إحالة مفقودة.

## أشياء لم أدّعِ اختبارها

- لم يتم تشغيل PowerShell 5.1 أو ملفات BAT/VBS على Windows فعلي.
- لم يتم تنفيذ التثبيت الأول أو تحديث نسخة مثبتة أو تجربة rollback على جهاز Windows.
- لم يتم توليد صورة أو فيديو فعلي من ComfyUI/GPU، ولم يتم تنفيذ طلب Ollama على جهاز المستخدم.
- لم يتم تشغيل مجموعة اختبارات Python في هذه الجولة؛ وجود الاختبارات لا يحل محل المراجعة اليدوية أو تجربة Windows الفعلية.

## خطوات تحقق الجهاز بعد مراجعة التغييرات

1. فك ZIP كاملاً إلى مجلد عادي.
2. شغّل `VERIFY-PACKAGE.bat` وتأكد من ظهور نجاح بصمات كل ملفات الحزمة.
3. شغّل `CHECK-STUDIO.bat` وتأكد من ظهور حالات ComfyUI وOllama من API الصحيحة.
4. احتفظ بسجل البيانات والنماذج كما هي؛ لا تحذف مجلد `CreativeStudioData` ولا أي مجلد نماذج.
5. نفّذ التحديث أولاً على نسخة احتياطية أو جهاز غير إنتاجي؛ راقب سجل `desktop-update` قبل الاعتماد النهائي.

**مهم:** لا أصف الإصدار بأنه اجتاز تشغيل Windows/GPU عملياً في هذه البيئة. هذه الحدود موضحة عمداً حتى لا تختلط مراجعة المصدر باختبار التنفيذ.
